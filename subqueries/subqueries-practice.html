Subqueries: a query inside a query

A subquery is a SELECT written inside round brackets ( ) within another query. The inner query runs first. Its answer is then used by the outer query.

Simple real-life example

Your class teacher asks: "Who scored more than the class average?" You can't answer it in one go. First you calculate the average (say 72 marks). Only then can you check each student's marks against 72.

SQL works the same way. The inner query finds the average. The outer query uses it:

concept
SELECT name FROM students
WHERE marks > (SELECT AVG(marks) FROM students);   -- inner query runs first
Scalar

Returns 1 value

One row, one column. Like a single number: the average fee, the highest age. Use it with = > <.

Multi-row

Returns a list

Many rows, one column. Like a list of IDs. Use it with IN, NOT IN, ANY, ALL.

Multi-row / column

Returns a mini table

Many rows and many columns. Compare pairs like (city, age), or use it in FROM as a table.

Golden rules
  • Always put a subquery inside brackets ( ).
  • If you use = or >, the subquery must give only one value. Otherwise PostgreSQL shows the error: "more than one row returned by a subquery used as an expression".
  • A subquery used in FROM should get a short name (alias), like AS t.
  • Run the inner query alone first. If it gives the right answer, the outer query will too.

Part 1

Scalar subquery: returns exactly one value

A scalar subquery gives back one single value (1 row × 1 column), for example the average age or the highest fee. You can use that value anywhere you would type a normal number: in WHERE, in SELECT, or in a calculation.

How to identifyThe inner query usually has AVG / MAX / MIN / SUM / COUNT without GROUP BY, or it filters on a unique value such as one student's name.

Example 1: students older than the average age

example
-- Outer query: show name and age of students
SELECT name, age
FROM students
-- keep only those whose age is greater than ONE number...
WHERE age > (
    -- ...and this inner query calculates that number: the average age (24.33)
    SELECT AVG(age) FROM students
);
Result: 5 rows (average age = 24.33)

Example 2: scalar subquery inside SELECT (compare each payment with the average)

example
SELECT payment_id,
       amount,
       -- same single value (average payment) is shown on every row
       (SELECT ROUND(AVG(amount)) FROM payments) AS avg_amount,
       -- amount minus average: positive = paid more than average, negative = less
       amount - (SELECT ROUND(AVG(amount)) FROM payments) AS diff
FROM payments;

Example 3: the most expensive course

example
SELECT course_name, fee
FROM courses
-- "=" works here because the inner query returns only ONE value
WHERE fee = (
    SELECT MAX(fee) FROM courses   -- highest fee = 25000
);
-- Why not ORDER BY fee DESC LIMIT 1?  If two courses had the same top fee,
-- LIMIT 1 would show only one of them. The subquery shows both.

Part 2

Multi-row subquery: returns a list

Here the inner query returns many rows but only one column, like a list of IDs. A list can't be compared with =, so we use special operators:

OperatorMeaning in simple words
IN (list)value is present in the list
NOT IN (list)value is not present in the list
> ANY (list)bigger than at least one item (bigger than the smallest)
> ALL (list)bigger than every item (bigger than the biggest)
< ALL (list)smaller than every item (smaller than the smallest)

Example 1: IN: students in costly courses (fee above ₹20,000)

example
SELECT name, course_id
FROM students
-- IN checks: is this student's course_id present in the list?
WHERE course_id IN (
    -- inner query returns a LIST of course ids: 1 (MERN) and 4 (Java)
    SELECT course_id FROM courses WHERE fee > 20000
);
Result: 7 rows

Example 2: NOT IN: students who have not paid anything

example
SELECT student_id, name
FROM students
-- keep students whose id is NOT present in the payments list
WHERE student_id NOT IN (
    SELECT student_id FROM payments   -- list of everyone who has paid
);
Result
student_idname

⚠ NOT IN and NULL: a common trapIf the inner list contains even one NULL, NOT IN returns zero rows. SQL can't be sure a value is "not equal to unknown". To be safe, add WHERE student_id IS NOT NULL inside the subquery.

Example 3: ALL: payments bigger than every cash payment

example
SELECT payment_id, amount, mode
FROM payments
-- > ALL means bigger than EVERY value in the list,
-- i.e. bigger than the biggest cash payment
WHERE amount > ALL (
    SELECT amount FROM payments WHERE mode = 'Cash'   -- list: 8000, 6000
);
-- Same result as: WHERE amount > (SELECT MAX(amount) FROM payments WHERE mode = 'Cash')
Result: 11 rows (every payment above ₹8,000)

Part 3

Multi-row, multi-column subquery: returns a mini table

Now the inner query returns many rows and many columns. There are two common ways to use it:

  • Pair comparison: WHERE (col1, col2) IN (SELECT a, b ...). Both values must match together, like matching both name and roll number.
  • Derived table: FROM (SELECT ...) AS t. The subquery acts as a temporary table that you can filter or join.

Example 1: youngest student of each course (pair comparison)

example
SELECT name, course_id, age
FROM students
-- match BOTH values together: (course_id, age) must be one pair from the list
WHERE (course_id, age) IN (
    -- inner query returns 2 columns: each course and its minimum age
    -- (1,21) (2,22) (3,20) (4,25)
    SELECT course_id, MIN(age)
    FROM students
    GROUP BY course_id
);
Result
namecourse_idage
Rohit Kumar121
Neha Jain425
Pooja Arora222
Riya Kapoor320
Why not just age IN (SELECT MIN(age) ...)?Then a 22-year-old in MERN would also match, because 22 is the minimum age of Data Analytics. Comparing the pair makes sure the age belongs to the same course.

Example 2: derived table: students who paid more than ₹20,000 in total

example
-- Outer query reads from the temporary table "t"
SELECT student_id, total_paid
FROM (
    -- inner query: one row per student with total of all instalments
    SELECT student_id, SUM(amount) AS total_paid
    FROM payments
    GROUP BY student_id
) AS t                       -- alias: name for the temporary table
WHERE total_paid > 20000;    -- now we can filter on the new column
Result
student_idtotal_paid
10123000
10723000
10925000
11123000
Same result with HAVING?Yes, GROUP BY student_id HAVING SUM(amount) > 20000 also works. A derived table becomes useful when you want to join or calculate further on that summary, as in the next example.

Example 3: derived table + JOIN: course-wise fee collection

example
SELECT c.course_name,
       t.paying_students,
       t.collected
FROM courses c
-- join the courses table with a summary table made by the subquery
JOIN (
    SELECT s.course_id,
           COUNT(DISTINCT s.student_id) AS paying_students, -- DISTINCT: a student with 2 instalments counts once
           SUM(p.amount)                AS collected        -- total money for that course
    FROM students s
    JOIN payments p ON p.student_id = s.student_id
    GROUP BY s.course_id
) AS t ON t.course_id = c.course_id   -- connect summary to course names
ORDER BY t.collected DESC;

Show the pending fee of every student who has paid something but not the full fee. Show name, fee, total_paid and pending, with the biggest pending amount first.

Show answer 
SELECT s.name,
       c.fee,
       t.total_paid,
       c.fee - t.total_paid AS pending          -- how much is still due
FROM students s
JOIN courses c ON c.course_id = s.course_id     -- to get the course fee
JOIN (
    -- derived table: total paid by each student
    SELECT student_id, SUM(amount) AS total_paid
    FROM payments
    GROUP BY student_id
) AS t ON t.student_id = s.student_id

ORDER BY pending DESC;

Quick cheat sheet

TypeReturnsUse withPattern
Scalar1 row × 1 col= <> > <, in SELECTWHERE fee > (SELECT AVG(fee) ...)
Multi-rowmany rows × 1 colIN, NOT IN, ANY, ALLWHERE id IN (SELECT id ...)
Multi-columnmany rows × many cols(a,b) IN, FROMWHERE (a,b) IN (SELECT x,y ...)
Derived tablea whole tableFROM / JOIN + aliasFROM (SELECT ...) AS t
Common errors
  • more than one row returned by a subquery used as an expression: you used = with a list. Use IN.
  • subquery has too many columns: IN got 2 columns but you compared 1. Use (a, b) IN or remove a column.
  • NOT IN returns nothing: there is a NULL in the inner list. Filter it with IS NOT NULL.
